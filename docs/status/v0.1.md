# Oxrail v0.1 status

- **Target:** `v0.1.0`
- **Milestone:** Guard Alpha + native interaction regression gate
- **Product status:** experimental and not accepted

## Shipping contract

- Installable as `oxrail@oxrail` from the `regrevia/Oxrail` marketplace.
- Human review/trust of bundled Hooks through `/hooks`; no automatic trust.
- Skill availability after a new thread/session.
- Side-effect-free setup verification with `INSTALLED`, `CONFIGURED`, and `VERIFIED` states.
- Passive first-browser-call verification when no harmless equivalent probe exists.
- Native Computer Use fail-open with Oxrail `BYPASSED` on Hook failure.
- Safety and Handoff status shown as `INACTIVE` unless their real capabilities are verified and effective.

`0.1.0-alpha.1` still exposes only the passive public verification adapter. Its internal Guard, Handoff, and Credential fixture foundations cannot activate Guard, Safety, Optimization, Handoff, or Credential claims; those require a real host adapter plus accepted version-bound evidence.

## Evidence status

The repository release gate and local evidence manifest are the source of truth for build/test acceptance. Real Chrome route coverage, micro-action granularity, performance improvement, and Secure Handoff are not inferred from local tests and remain unclaimed until a version-bound Host Profile proves them.

## Public claims

Allowed after the repository gate passes:

- the plugin/Skill/hooks package installs from the documented marketplace;
- setup and passive-verification logic behave as tested;
- Oxrail preserves native execution when its own Hook path is unavailable.

Not claimed without additional host evidence:

- every Chrome Computer Use call is intercepted;
- per-click Guard coverage;
- total token or latency reduction;
- ChatGPT Web lifecycle-hook support;
- active Secure Handoff or end-to-end secret non-observability.
